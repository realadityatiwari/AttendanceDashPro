# PREREQUISITES
Before executing this prompt, you MUST:
1. Read `docs/17_AI_HANDOFF.md` and `docs/22_AI_WORKING_CONTEXT.md`.
2. Understand that `ui.js` is a pure consumer and contains NO business logic.

# INSTRUCTIONS

Implement the UI/UX changes with strict adherence to the project's styling and structural rules.

### 1. Pure Consumer Rule
Never calculate math, determine dates, or check eligibility in `ui.js`. The UI takes pre-calculated data models (e.g., `QuizDashboardModel`) generated by the engines and converts them into HTML strings.

### 2. Cross-Platform Parity
Build the UI natively for both Desktop and Mobile Web. Use CSS Flexbox/Grid and media queries (`@media (max-width: 768px)`). Do not rely on JavaScript viewport checks for layout unless injecting entirely different component structures (e.g., the mobile accordion vs desktop tables).

### 3. CSS Conventions
- Use CSS Custom Properties (Variables) defined in `:root` for all colors and spacing to support Dark/Light themes natively.
- Avoid inline styles.
- Do not use CSS frameworks (Tailwind, Bootstrap). Use Vanilla CSS.

### 4. DOM Manipulation
- The app uses a bulk render strategy (`recalculateAndRender()`). 
- Construct HTML strings using template literals and set `innerHTML`.
- Rebind event listeners via DOM delegation in `app.js` if the parent containers are re-rendered.

### 5. UX Considerations
Ensure the interface feels native on mobile (PWA). Use bottom sheets for forms, large tap targets (min 44px), and native smooth scrolling.
