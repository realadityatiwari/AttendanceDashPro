# S4.3 — Academic Events Engine

## Architecture

In Phase S4.3, we finalized the central invariant of the Academic Events subsystem:
**ACADEMIC EVENT = EXACT-DATE SCHEDULE MUTATION**

An academic event does not create a historical or future attendance *record*. It mutates the *calendar schedule* itself for the selected date.

The core flow is:
**EVENT -> CALENDAR / SCHEDULE -> CLASS OCCURRENCE -> ATTENDANCE ENGINE -> CURRENT / OVERALL / FORECAST**

### Changes Made
1. **`getEffectiveDaySchedule(dateString)`**: Introduced in `calendar-engine.js`. This is the single source of truth for the daily schedule. It retrieves the static day schedule and natively applies events (EXTRA_LECTURE, CLASS_CANCELLED, PUBLIC_HOLIDAY) onto the array of class occurrences.
2. **UI Integration**: `ui.js` now uses `getEffectiveDaySchedule(dateString)` instead of `getMergedDaySchedule`. This allows the UI to naturally render extra classes and hide cancelled classes on exact dates.
3. **Attendance Engine Unification**: `attendance-engine.js` was updated to iterate over `getEffectiveDaySchedule`. This elegantly removed the need for the manual "delta application" loops that existed previously. The attendance engine now naturally increments `tot` and `pending` precisely because the underlying class occurrence natively exists (or is removed).
4. **Unique Identification**: Extra classes are appended to the schedule with uniquely identifiable types (e.g., `L_extra_<eventId>`). `utils.js` normalizes this back to `L`, `T`, or `P` for statistical counts. This gives each extra class a unique `classId` (e.g. `2026-08-10:BCS-501:L_extra_evt1`), allowing the UI state to track independent "Attended/Missed/Pending" records for multiple extra classes in a single day without colliding.

### Event Definitions
- **Cancellations (`CLASS_CANCELLED`)**: Actively removes one matching class occurrence from the daily schedule. 
- **Extra Classes (`EXTRA_LECTURE`, `EXTRA_TUTORIAL`, etc)**: Actively injects a new class occurrence into the daily schedule.
- **Closures (`PUBLIC_HOLIDAY`, `EMERGENCY_CLOSURE`)**: Disables the entire day (marks `isWorkingDay = false`), removing all class opportunities natively.

### Verification
The invariants are tested and proven by `js/test-events-controller.js`, running 12 independent test assertions covering:
- Exact-date mutations
- Past/Future scoping
- Closure behavior
- Subject/Class Type isolation
- Interactions with current vs forecasted domains
