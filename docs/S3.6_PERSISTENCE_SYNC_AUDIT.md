## 3. Defects Found & Fixed

### P0 — Lab experiments silently blocked ALL cloud syncs (fixed)
**Symptom:** laboratory state never reached Firestore; `isDirty` stuck `true`; every subsequent sync (attendance/events too) failed silently (console-only error):
`Unsupported field value: undefined (found in document students/{uid})`.

**Root cause:** `saveLaboratoryStates` serialized `title/marks/remarks` which are `undefined` for experiments created by `logExperiment` (only `experimentNumber`, `signatureStatus`, `dateConducted` set). Firestore rejects any `undefined` field and rejects the **entire** `set()` call — the whole payload (profile, settings, attendance, events, lab) was dropped.

**Fix (defense in depth):**
1. `js/storage.js` `saveLaboratoryStates` — omit keys whose value is `undefined`.
2. `js/storage.js` `performCloudSync` — recursive `JSON.parse(JSON.stringify(payload))` sanitizer before `set()`, so no future state field can poison the payload.

**Verification:** lab sync probe → `Cloud sync complete`, `isDirty:false`, Firestore `laboratory` populated; cross-device round-trip hydrates lab in Session B.

### P1 — Unsynced local mutation silently overwritten by stale cloud (fixed)
**Symptom (S3.4 documented limitation, empirically confirmed):** a mutation made offline, or one whose 400 ms debounce never fired before reload, existed only in localStorage; the next online hydration merged cloud-wins and silently reverted the local change.

**Empirical proof (pre-fix):** event active `false` → offline toggle → `active:true` local, `isDirty:true` → reload before debounce → online re-hydration → `active:false` (mutation lost, cloud `false` won).

**Root cause:** `initLocalState` never restored `isDirty`, and `fetchCloudStates` merged cloud-over-local unconditionally with no local-dirty guard.

**Fix:**
1. `initLocalState` — restore `AppState.isDirty = parsed.isDirty === true`.
2. `fetchCloudStates` — if `AppState.isDirty`, flush local to cloud (`await performCloudSync(uid, false)`) **before** downloading, matching the documented "local is authoritative on refresh" invariant.

**Verification:** same scenario post-fix → after online re-hydration local and cloud are `active:true` (mutation preserved + propagated). Regression-covered by `test-persistence-sync.js` (set-before-get order assertion).

### P2 — Stale `signedOn` retained after un-signing (fixed)
`toggleLabSignature` flipped back to `pending` but left `signedOn` set. Fixed in `js/ui.js`: `delete exp.signedOn` on un-sign. Verified through the real UI at 1440 px: `signed`(signedOn present) → `pending`(signedOn removed locally **and** in Firestore after sync).

## 4. Verified Behaviors (not changed)

- **Offline resilience is BETTER than S3.4 documented.** Firestore client-side offline persistence (enabled in the compat SDK) queues `set()` while offline; the write resolves ("Cloud sync complete", `isDirty=false`) and is auto-flushed to the backend on reconnect — **no app-level reconnect listener is needed for the debounce-elapsed case**. Confirmed: offline toggle → online (no reload) → cloud flushed.
- **`fetchCloudStates` is a naive per-key cloud-wins merge** — no timestamps, no conflict resolution. Acceptable for single-primary-device usage; documented limitation (see §6).
- **Simulation mode is in-memory only** (`dateContext.simulationAttendance`), never written to Firestore; `logClassState` is the single write-authority deciding persist-vs-memory. Events/holiday handling excludes simulation attendance correctly.
- **No reconnect auto-flush in app code** (`pwa.js` only toggles the offline banner) — the offline case is covered by Firestore's own queue + the new dirty-flush on hydration.
- Events round-trip, attendance round-trip, profile, and settings round-trip all verified cross-device.

## 6. Known Limitations (unchanged, documented)

- **No multi-device conflict resolution.** `fetchCloudStates` is last-write-wins per key (cloud wins on same key). Concurrent edits from two devices can clobber each other. Out of scope for S3.6 (single-device-primary assumption).
- **`AppState.settings.simulationMode` is stored and synced but unused** — `dateContext` derives mode from the selected date. Dead setting; left in place (removing is out of scope).
- **`AppState.history` is a dead field** — never written by any caller; not part of the Firestore payload.
- **No app-level reconnect flush listener** — an in-tab (no reload) offline mutation whose debounce never fired is only flushed on the next mutation or the next hydration reload. The reload-before-debounce case is now safe (dirty-flush); a same-tab lost-write window effectively does not exist once the debounce fires (Firestore queue).
- The 400 ms debounce remains (S3.5 tuning); combined with the dirty-flush it no longer risks data loss on fast reloads.
