# S3.2 Functional Gap Audit

## 1. Executive Summary
The application architecture is remarkably solid. The core Three-Engine pipeline (Calendar -> Attendance -> Quiz) computes complex academic realities correctly. However, while the *backend math* is rigorous, several crucial user-facing features (Laboratory, Academic Events, Cloud Sync) are significantly incomplete or entirely broken in their current state. The application cannot be considered reliable for daily student use until these gaps are closed.

## 2. Audit Methodology
The codebase was inspected statically, focusing on end-to-end data flow (UI → Controller → Engine → Storage → Sync). All known architectural bugs (from `15_KNOWN_BUGS_AND_TECHNICAL_DEBT.md`) were verified against the current source code implementation. Existing regression suites were executed to establish a baseline.

## 3. Current Application Surface
The application currently exposes: Authentication, Dashboard (Current Date), Quiz Trackers, Laboratory Dashboard, Academic Tools (Events), and Profile.

## 5. 🟢 WORKING Features
- **Authentication**: Login, Signup, and Profile hydration work end-to-end.
- **Calendar Engine**: Correctly resolves working days, holidays, and timelines.
- **Attendance Engine**: Correctly handles L/T optimization and safe skips.
- **PWA / Offline**: Caches assets and functions offline (events controller caching fixed).

## 6. 🟡 PARTIALLY WORKING Features
- **Attendance Logging**: While marking Present/Absent works, the UI lacks a straightforward "Undo to Pending" action, requiring the user to toggle awkwardly.
- **Academic Events**: Event creation works and properly mutates the Calendar Engine, but events are blocked from cloud sync due to strict Firestore rules. Data only lives in `localStorage`.
- **Quiz System**: Valid for most subjects, but specific applicability rules for edge cases (e.g., BCS-054 Q3) remain ambiguous (awaiting academic verification).

## 7. 🔴 BROKEN Features
- **Laboratory System**: `computeLaboratoryDashboard` relies on `stats.totP` and `stats.attP_done`, but the `AttendanceEngine` does not currently calculate or export these variables in `subjectStatsArray`. As a result, laboratory attendance percentages permanently evaluate to 0%, regardless of logged experiments.
- **Firebase Sync (Lab & Events)**: `firestore.rules` rejects writes containing `laboratory` or `academicEvents` fields at the root of the user document (BUG-001). This causes silent failures where data is entirely lost if `localStorage` is cleared.

## 8. ⚪ MISSING Current-Semester Features
- Explicit UI for clearing a logged class (reverting to 'Pending' instead of toggling between 'Present' and 'Missed').
- Comprehensive Empty/Error/Loading UI states across all dashboards.

## 9. 🟠 MISLEADING UI/Features
- **Laboratory Progress**: The UI renders a progress bar and percentage that will statically remain at 0% due to the missing engine properties.
- **Academic Events**: The UI allows creating events, heavily implying they are securely stored to the user's profile, while they are actively being rejected by Firestore.

## 10. ⚫ DEAD/UNUSED Code/UI
- The dual-write logic in `events-controller.js` (DEBT-001) writes to both `runtimeEvents` and `AppState`, which presents an architectural risk of divergence.
