## 2. Architectural Baseline (Frozen Modules)

This section freezes the exact architecture. For each module: responsibility,
owner of state, allowed/forbidden dependencies, public API, persistent-state
interaction, and invariants.

### 2.1 Calendar Engine (`js/calendar-engine.js`)

- **Responsibility**: Sole temporal authority — working days, holidays, quiz/attendance
  windows, event priority resolution, event validation/normalization.
- **Owner of state**: `l1StaticData` (frozen `AcademicCalendar`), `l2MemoryCache`
  (`getAcademicDay` result cache), `runtimeEvents` (derived, injected via
  `syncRuntimeEvents`).
- **Allowed dependencies**: none (leaf / pure module).
- **Forbidden dependencies**: any other module (engines, UI, storage, controllers).
- **Public API**: `initCalendarEngine`, `getPolicy`, `getQuizPolicy`,
  `getCalendarEventsByType`, `syncRuntimeEvents`, `validateAcademicEvent`,
  `createAcademicEvent` (pure normalizer/validator — does NOT mutate persistent state),
  `getSubjectEventDeltas`, `getAcademicDay`, `addDays`, `getTodayString`,
  `getPreviousWorkingDay`, `getNextWorkingDay`, `getTeachingDaysBetween`,
  `getWorkingDaysUntil`, `getSubjectTimeline`, `getSubjectMilestones`,
  `getPreviousMilestone`, `getNextMilestone`, `getAttendanceWindow`,
  `getQuizWindow`, `getWindowTeachingDays`, `getRemainingTeachingDays`,
  `AcademicEventRegistry`.
- **Persistent-state interaction**: none. `runtimeEvents` is populated exclusively
  by `syncRuntimeEvents(AppState.academicEvents)` called by the controller/app.
- **Known invariants**: dates are `YYYY-MM-DD` strings; `AcademicDay` returns are
  frozen; L2 cache cleared whenever runtime events change; Calendar Engine never
  imports or mutates `AppState`.

### 2.2 Attendance Engine (`js/attendance-engine.js`)

- **Responsibility**: Sole attendance-mathematics authority — counts, percentages,
  optimization (must-attend / safe-skip), aggregate/ERP statistics, tooltip impact.
- **Owner of state**: none (pure functions; receives `states` as a parameter).
- **Allowed dependencies**: `utils.js`, `calendar-engine.js`.
- **Forbidden dependencies**: `quiz-engine.js`, `laboratory-engine.js`, UI, storage,
  controllers.
- **Public API**: `calcCurrentPct`, `calcForecastPct`, `calcAvgPct`,
  `meetsAttendanceTarget`, `optimize`, `optimizeLive`, `getSubjectQuizOptimization`,
  `getAttendanceData`, `computeSubjectStats`, `assertConsistency`,
  `computeOverallStats`, `computeCurrentOverallAttendance`,
  `computeForecastOverallAttendance`, `calcForecastImpact`.
- **Persistent-state interaction**: none — reads attendance through the `states`
  argument (LIVE or simulation overlay) supplied by the UI/date context.
- **Known invariants**: `att + miss + pending = total` per class type; P1/P2
  normalize to `P`; `computeSubjectStats` exports `totP/attP_done/missP_done/
  pendingP/completedP` (S3.4 contract, consumed by Laboratory Engine).

### 2.3 Quiz Engine (`js/quiz-engine.js`)

- **Responsibility**: Pure academic-rules engine — evaluates quiz eligibility from
  Attendance Engine optimization results against Calendar Engine quiz policy.
- **Owner of state**: none.
- **Allowed dependencies**: `calendar-engine.js`, `attendance-engine.js`.
- **Forbidden dependencies**: attendance calculation logic, UI, storage.
- **Public API**: `computeQuizEligibility`, `computeQuizDashboard`.
- **Persistent-state interaction**: none — reads `states` (attendance) and
  `timetable` as arguments.
- **Known invariants**: eligibility is binary; `eligible = reachable && deficit === 0`;
  Quiz Engine never recalculates attendance math.

### 2.4 Laboratory Engine (`js/laboratory-engine.js`)

- **Responsibility**: Lab experiment tracking, completion rule (signed + attended),
  milestone evaluation.
- **Owner of state**: none (computes from raw lab + attendance arguments).
- **Allowed dependencies**: `utils.js`.
- **Forbidden dependencies**: `attendance-engine.js` (reads attendance state via a
  raw argument, not an import), UI, storage.
- **Public API**: `computeLaboratoryDashboard`, `LAB_RULES`.
- **Persistent-state interaction**: reads `AppState.laboratory` (passed as argument)
  and physical attendance state; never writes.
- **Known invariants**: 10 experiments per subject; completion requires both
  signature `'signed'` and physical `'Attended'`; derived fields never persisted.

### 2.5 Storage Layer (`js/storage.js`)

- **Responsibility**: `AppState` singleton, localStorage persistence, debounced
  Firestore sync, hydration, legacy V1 migration.
- **Owner of state**: `AppState` (all persistent runtime state).
- **Allowed dependencies**: `firebase.js`.
- **Forbidden dependencies**: any engine module.
- **Public API**: `AppState`, `initLocalState`, `persistLocalState`, `loadStates`,
  `saveStates`, `loadLaboratoryStates`, `saveLaboratoryStates`, `clearStates`,
  `fetchCloudStates`, `triggerCloudSync`, `isProfileComplete`, `getLocalAttendance`,
  `clearLocalAttendance`.
- **Persistent-state interaction**: sole persistence authority; sync payloads are
  `undefined`-scrubbed; writes use `{ merge: true }`.
- **Known invariants**: see §7 (Persistence Contract).

### 2.6 Events Controller (`js/events-controller.js`)

- **Responsibility**: Exclusive mutation interface for academic events.
- **Owner of state**: `AppState.academicEvents` (mutated through this controller only).
- **Allowed dependencies**: `storage.js`, `calendar-engine.js` (validate + normalize +
  sync), `ui.js` (single allowed reverse-layer import: `recalculateAndRender`),
  `firebase.js`.
- **Forbidden dependencies**: rendering logic, business-rule logic.
- **Public API**: `createAcademicEvent`, `updateAcademicEvent`,
  `toggleAcademicEvent`, `archiveAcademicEventController`.
- **Persistent-state interaction**: all mutations flow through
  `processEventMutation` (snapshot → mutate → sync runtime → persist local → cloud
  sync best-effort → re-render; revert on persist failure).
- **Known invariants**: `AppState.academicEvents` is the sole persistent authority;
  `runtimeEvents` is derived; no hard delete — archive is terminal.

### 2.7 UI Layer (`js/ui.js`)

- **Responsibility**: Pure rendering — reads engine outputs, builds HTML strings,
  injects into DOM. Owns the master refresh function `recalculateAndRender()`.
- **Owner of state**: `currentQuiz` (module-level tab index — a known design debt,
  DEBT-007).
- **Allowed dependencies**: `storage.js`, `utils.js`, `attendance-engine.js`,
  `laboratory-engine.js`, `quiz-engine.js`, `dateContext.js`, `calendar-engine.js`.
- **Forbidden dependencies**: `events-controller.js` (reverse); business logic.
- **Public API**: `recalculateAndRender`, `renderQuizTabs`, `switchQuiz`,
  `renderDateNavigator`, `renderBottomSheetDateNav`, `renderAcademicEvents`,
  `renderTodayClasses`, `renderHistoryLog`, `logAttendance`, `logExperiment`,
  `toggleLabSignature`, `updateThemeBtn`, and the component builders.
- **Persistent-state interaction**: writes only via `dateContext.logClassState()`,
  `saveLaboratoryStates()`, and controller calls — never directly to `AppState`.
- **Known invariants**: viewport branch only for rendering; engines never import UI;
  UI never orchestrates engines.

### 2.8 Auth Layer (`js/auth.js` + `js/firebase.js` + `js/validation.js`)

- **Responsibility**: Firebase init, login/signup/logout, roll/password validation,
  profile save.
- **Owner of state**: `AppState.profile` (via auth flows and `saveProfile`).
- **Allowed dependencies**: `firebase.js` (auth), `storage.js` (profile/sync),
  `validation.js`.
- **Forbidden dependencies**: engine modules.
- **Public API**: `loginUser`, `signupUser`, `logoutUser`, `getInternalEmail`,
  `validateRollNumber`, `validatePassword`, `validateSignupForm`, `saveProfile`
  (app.js), `isProfileComplete`.
- **Persistent-state interaction**: logout purges `app_state_{uid}` from localStorage
  (S3.9 fix) then signs out; login hydrates local-first then fetches cloud.
- **Known invariants**: roll number is exactly 13 digits; internal email
  `{roll}@student.app`; session persistence `LOCAL`.

### 2.9 PWA Layer (`js/pwa.js`, `service-worker.js`, `manifest.json`)

- **Responsibility**: SW registration (version-parameterized), install prompt,
  offline/online banner, reconnect sync trigger.
- **Owner of state**: none (browser-level).
- **Allowed dependencies**: `utils.js` (`APP_VERSION`), `storage.js`
  (`triggerCloudSync` — S3.7/S3.9 reconnect flush).
- **Public API**: `initPWA` (pwa.js); SW lifecycle install/activate/fetch (service-worker.js).
- **Persistent-state interaction**: SW never stores user state; only static assets.
- **Known invariants**: see §8 (PWA Baseline).

## 7. Persistence Contract (frozen)

| Invariant | Frozen behavior |
|---|---|
| **Local-first** | Hydrate from `localStorage` (`app_state_{uid}`) on login, render immediately, then `fetchCloudStates()` in background. |
| **`isDirty` semantics** | `true` when local state is ahead of cloud. Restored from localStorage on hydration (S3.6 P1 fix). Cleared after successful cloud write + re-persist. |
| **400ms debounce** | `triggerCloudSync()` debounces `performCloudSync` by 400ms. It persists local state immediately before debouncing. |
| **Dirty flush before cloud hydration** | `fetchCloudStates()` runs `performCloudSync(uid, false)` BEFORE downloading when `AppState.isDirty` is true (local is authoritative on refresh). |
| **Firestore merge behavior** | All writes are `set(payload, { merge: true })`. Payload is recursively scrubbed of `undefined` before `set()`. |
| **Logout state purge** | `logoutUser()` removes `app_state_{uid}` from localStorage before sign-out and reload (S3.9 fix). |
| **Offline behavior** | Writes land in localStorage with `isDirty=true`; Firestore's client offline queue queues `set()` and auto-flushes on reconnect (debounce-elapsed case). |
| **Reconnect behavior** | `pwa.js` `online` event fires `triggerCloudSync()` (S3.7/S3.9 fix). No other app-level reconnect listener exists. |
| **Cross-session behavior** | Attendance/lab/events/settings/profile round-trip across devices via Firestore; per-key cloud-wins merge on hydration; no conflict resolution (accepted limitation). |
| **Simulation** | `dateContext.simulationAttendance` is in-memory only; never persisted; cleared when returning to LIVE. |

## 9. Accepted Limitations (intentional, not bugs)

These are **accepted limitations** of the current-semester product. They are
documented so future work can either preserve or intentionally supersede them.

1. **Current-semester configuration is intentionally narrow.** The product targets
   one section/batch (CSE-51, V Semester, 2026–27). Configuration is a single
   `timetable.json`; no runtime semester/branch/department selector exists.
2. **Current B.Tech branch/timetable assumptions remain.** Subject codes, day
   schedule, and timelines are B.Tech CSE-specific.
3. **BCS-054 Q3 is unresolved.** See §3. Not converted to a guessed value.
4. **Browser Back does not provide internal History API routing.** View switching is
   state-based; browser history is not integrated into app navigation.
5. **Accessibility has only partial/deferred deep verification.** Semantic HTML and
   basic contrast are present (S3.9 §11); deep a11y testing is deferred.
6. **No multi-device conflict-resolution system.** Cloud hydration is per-key
   cloud-wins; concurrent two-device edits can clobber (single-device-primary assumption).
7. **No generalized semester/branch/department configuration system yet.**
   Multi-tenancy is a future Phase-4 concern.
8. **`AppState.settings.simulationMode` is stored but unused** (dead setting);
   `AppState.history` is a dead field (DEBT-008).
9. **No app-level reconnect flush listener** beyond the SW `online` trigger; the
   reload-before-debounce race is closed by the hydration dirty-flush.

## 10. Frozen Architectural Invariants

These are **non-negotiable** for any future change unless an intentional migration
replaces them.

1. Calendar Engine remains the **sole temporal authority**.
2. Attendance Engine remains the **sole attendance-calculation authority**.
3. Quiz Engine remains the **sole quiz-rule consumer**.
4. Laboratory Engine **owns laboratory calculations**.
5. UI **does not own business state**.
6. Academic Events mutate **through `events-controller`** only.
7. `AppState` is the **persistent runtime state authority**.
8. Calendar runtime events remain **derived state** (`runtimeEvents` ← `syncRuntimeEvents(AppState.academicEvents)`).
9. `timetable.json` remains the **current-semester academic configuration**.
10. Firestore rules remain the **security boundary**.
11. Local dirty state is **authoritative during refresh** (flush-before-download).
12. **No duplicate academic rules** anywhere.
13. **No direct UI mutation of engine state**.
14. **No engine imports from UI/storage/controller**.
15. Service Worker must **not become a state-storage mechanism**.
