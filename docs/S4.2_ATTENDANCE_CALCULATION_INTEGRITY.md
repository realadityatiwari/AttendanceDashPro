# S4.2 Attendance Calculation Integrity

## 1. Existing Calculation Model
The core computation lives inside `js/attendance-engine.js`. 
- **Timetable:** Represents the static academic schedule.
- **Calendar Engine:** Resolves the timetable against dates to generate scheduled classes, overriding standard schedules with `AcademicEvent`s.
- **Attendance Engine:** Compares the output of the calendar against stored states (`AppState.attendance`) to calculate percentages.
- **Quiz Engine:** Iterates over isolated Quiz Windows from the calendar to calculate eligibility metrics independently of overall standing.

## 2. Current Attendance Definition
**Verified.** `computeCurrentOverallAttendance()` strictly calculates:
`att_done` / (`att_done` + `miss_done`).
Pending classes (which represent future schedule opportunities or unlogged past classes) are excluded from the denominator. Future classes CANNOT mathematically reduce the current attendance percentage.

## 3. Overall Attendance Definition
**Verified.** Represents 15 July 2026 → selected/current date. The core `computeCurrentOverallAttendance` natively iterates over all classes up to the current date and ignores the timeline milestones used by the Quiz Engine. It safely aggregates L, T, and P classes without requesting Quiz targets.

## 4. Forecast Definition
**Verified.** `computeForecastOverallAttendance()` explicitly assumes all pending classes are attended. 
`forecast = (att_done + pending) / (att_done + miss_done + pending)`.
This calculation projects future scenarios without writing or mutating historical attendance states in `localStorage` or Firestore.

## 5. Date Boundary Behavior
**Verified.** `calendar-window.js` safely enforces that calculations do not project beyond the specified timeline milestones. The overall loop stops precisely at the active context date (`dateContext.js`).

## 6. Subject Commencement Behavior
**Verified.** Subjects support custom `commencementDate` fields in `timetable.json`. If a subject begins late (e.g., July 25 instead of July 15), classes scheduled before July 25 are mathematically excluded from the denominator.

## 7. Practical Subject Behavior
**Verified.** Practical subjects natively generate `P` counts. `computeCurrentOverallAttendance` seamlessly aggregates these classes. Furthermore, `optimizeLive` (used for Quiz logic) explicitly skips evaluating subjects without `L` or `T` counts (`hasLorT = totL + totT > 0`), ensuring practicals never erroneously declare quiz ineligibility.

## 8. Academic Event Interaction
**Verified.** 
- Events (like `EXTRA_LECTURE` or `CLASS_CANCELLED`) mutate the total scheduled array dynamically in the `Calendar Engine` via `getSubjectEventDeltas()`.
- The Attendance Engine transparently adapts to these deltas without fabricating permanent `Attended` or `Missed` records, preserving the separation of Schedule vs. Record.

## 9. Quiz Engine Boundary
**Blocker Addressed.**
- Previously, `computeSubjectStats()` internally calculated quiz eligibility metrics (`targetPercentage`, `lectureDeficit`) and returned them in `optResult`, causing Quiz semantics to leak into generic Overall cards.
- The `quiz-engine.js` correctly owns its own `getSubjectQuizOptimization()` loop.
- **Resolution:** I appended explicit `current` and `forecast` objects to the returned model, marking `optResult` for eventual deprecation while retaining it strictly for legacy UI compatibility until Phase S4.4/S4.6.

## 10. Bugs Found
- **B1:** `optResult` calculation was hardcoded inside the generic subject stats aggregator, entangling the dashboard with a 75% target assumption.

## 11. Fixes Made
- Updated the `computeSubjectStats` output contract to separate `raw`, `current`, and `forecast` objects.
- Added four explicit automated assertions guaranteeing the engine isolates current outcomes from forecast projections.

## 12. Tests Added
- Added `S4 Contract` assertions inside `js/test-attendance-engine.js` to guarantee the engine returns explicitly separated `current` and `forecast` objects.

## 13. Exact Test Results
- Run command: `node js/test-attendance-engine.js`
- **Result:** 30+ assertions in the file passed. Engine output structure perfectly validated.

## 14. Remaining Limitations
- `ui.js` still utilizes the flat legacy properties (e.g., `totComb`, `currentAvgPct`). The new `current`/`forecast` objects remain latent in the data structure, awaiting UI adoption in Phase S4.4/S4.6.

## 15. Final Engine Contract for S4 UI
The UI can now safely consume:
```json
{
  "subject": { "code": "BCS-501", "name": "DBMS", "tag": "Core" },
  "raw": { "totL": 10, "attL_done": 8, "pendingL": 2, "completedL": 8, ... },
  "current": {
    "lecture": 100.0,
    "tutorial": null,
    "practical": null,
    "overall": 100.0
  },
  "forecast": {
    "lecture": 100.0,
    "tutorial": null,
    "practical": null,
    "overall": 100.0
  }
}
```
This isolates the domains cleanly for future dashboard rendering.
